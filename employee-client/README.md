# 员工端 1.1.0：原系统页面与自动同步

先将主机更新到V3.26.0，再完整解压本员工包。首次运行InstallEmployee.cmd，已安装运行UpdateEmployee.cmd；升级保留当前用户的data，不要删除本机待同步数据。自带官方Node.js 24 LTS Windows x64运行环境，无需安装Node.js、管理员权限或下载运行依赖。旧1.0版独立工作台须用本完整包升级一次。

桌面Orbit Employee打开本机127.0.0.1:3199。首次只需填写主机根地址（例如http://192.168.1.165:3000），随后就是原系统登录、项目、列表、详情、上传与提交页面。首次必须连接主机，登录并完成页面和资料同步，才可离线使用。主机仍通过原网页版使用，无需员工端。

正常操作原页面即可。跨境线索／母版／产品，短视频图文／视频和素材中心的新增、文件与资料修改、提交先保存本机；断网或主机关机时保留，联网且主机服务恢复后自动上传并执行原来点击的提交。不会要求再次提交。本地新建来源依赖会自动换成主机真实编号；分块断点续传、SHA-256校验、重复请求防重。短视频已退回内容可按原入口提交新版本。未同步状态显示“待同步”；不是主机已经收到。

窗口底部显示轻量同步状态；只有权限变化、来源失效或编辑冲突等异常才需处理。本机旧内容不能自动覆盖主机新版本。异常时可重试、保留本机内容并查看主机版本、导出本机选入的附件。审核、角色／权限配置、归档删除、单独追加备注等依赖主机实时状态的操作需要联网，本版没有把所有管理操作变成离线成功。

启动和每分钟后台同步有权限项目的近期正常资料（每类至多100条）及相关表单选项；后台读取不清空未读标记。更新不会重置正在编辑的表单。自动缓存小图片，查看原文件时加入后台缓存；视频等大文件未完成缓存前不能离线观看。不是把所有历史文件复制到员工电脑。约5GB的文件缓存按最近访问淘汰；未同步附件不参与淘汰，会额外占用磁盘，空间不足会报错并保留已写入内容。已完成上传的本机文件逐步转入可淘汰缓存。不要手动删除data、让清理软件清除队列，或在未确认同步前卸载。

默认同步限速512KB/s，每轮小图预热有预算，上传优先于历史缓存；可通过原有本机设置API调节。后台同步需要员工电脑处于开机、员工会话已登录且程序运行。首次缓存可能需要等待；不能保证刚安装且从未连接主机就打开系统。Windows登录后启动后台，关闭网页不会停止同步。主机要开机且服务运行才能接收或下发变化。

按主机固定身份和员工ID隔离缓存；项目入口、页面权限和普通成员／项目长可见范围在主机重新校验，撤权联网后清理不可见历史，保留待同步附件。离线许可7天，超期要联网验证。离线时无法即时获知撤权。本机文件靠操作系统用户目录权限保护，并非防本机管理员的加密保险库；不保存登录密码，会话加密保存。

HTTPS同源支持后台校验更新，HTTP局域网采用完整员工包人工更新。将来HTTPS远程访问可沿用队列；改地址需登录同一主机账号。手机离线端本版未实现。

验证：Linux环境完成服务端、队列、重启、离线原页面与恢复自动提交测试；Windows安装脚本仅做语法与包完整性检查，未在Windows实机安装。建议先用一台员工电脑验收，再分发。
