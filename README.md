# 公司短视频内容中台

面向公司局域网的素材、内容与发布协作平台。当前 V3.6 增加工作报备中心、日报接收/抄送和回收站只读预览，并保留 V3.5 的内容池与筛选改动。

## V3.6 更新

新增工作报备中心：有创建权限的账号可保存或提交日报，有接收权限的账号查看接收内容，有抄送权限的账号对已提交日报抄送其他账号；日报接收状态与抄送已读状态分开记录。回收站条目增加只读预览，预览不会提供恢复、编辑或删除操作。

## V3.5 更新

内容池四个状态窗口只展示封面和数量；勾选、批量改名、批量备注、提交、撤回、归档和回收站操作统一放在展开后的状态窗口中。所有业务列表的筛选条件栏支持添加多个字段，并且、或者、排除三种关系，上传时间可直接按开始和结束日期筛选。推荐案例评语在列表中最多展示两行，所有主要弹窗的标题和关闭按钮在滚动时保持可见。

本版更新与验收项目见 [V3.5-内容池与筛选更新验收说明.md](V3.5-内容池与筛选更新验收说明.md)。数据库、媒体目录、已有内容和员工配置继续保留。

## 本地运行

```bash
pnpm install
pnpm run dev --host 127.0.0.1
```

浏览器打开 `http://127.0.0.1:3000`。默认数据库位于 `data/database`，文件位于 `data/media`；正式部署通过 `ORBIT_DB_PATH` 和 `ORBIT_MEDIA_DIR` 分开配置。

## Windows 公司内网部署

Windows 10 服务器部署脚本与操作说明位于 `deploy/windows`。生产环境使用服务器本地 SQLite 数据库和独立文件目录，不再依赖 Cloudflare 本地模拟服务。默认只开放公司专用网络的 3000 端口，并创建开机启动与每日数据库备份任务。

## 数据规则

- 平台分为素材中心、内容中心和发布中心；素材与内容不建立强制关联。
- 内容小组必须归入一个短视频账号；同一短视频账号允许建立多个内容小组。
- 素材按“产品 + 目标账号 + 素材套”上传，审核通过后入库；账号下各内容组成员可以非独占领取。
- 人员权限由“角色功能权限”和“账号/小组业务范围”共同决定，任一不满足都不能操作。
- 审核通过的内容自动进入原所属账号的发布池；跨账号复用需复制为新内容并重新审核。
- 多名发布人员可共同负责一个账号；点击“开始发布”才锁定任务，查看不会抢占，释放和改派保留日志。
- 发布管理支持当前筛选结果全选与批量下载；视频保留原文件，图文按内容分文件夹后统一打包。

- 平台统一维护抖音、快手、小红书等基础资料。
- 店铺和短视频账号各自归属一个平台；商品同时保存所属平台和店铺。
- 内容默认仅上传人和管理员可见，有权限的角色可以设置为全部可见。
- 工作台使用一张去重后的“我的待办”，最多10条：未完成审核队列优先，其次是本人驳回、本人草稿，最后是等待最久的新审核任务。
- 没有审核查看权限的账号不展示整个审核模块；没有操作权限的按钮和说明不占用页面空间，权限变化后自动返回工作台。
- 内容池支持批量上传，第一版单次最多 20 条、同时处理 3 个文件；统一标题会自动生成 001、002、003 后缀。
- 上传窗口提供“上传并提交”“保存为草稿”“退出”三个出口；退出需二次确认，并清理本次尚未完成的内容记录和文件。
- 内容标题和内容类型必填，关联商品与所属账号可保持“未分配”；内容列表支持批量撤回、改名称、写备注、提交和删除。
- 内容池与审核工作台共用同一套内容详情字段和排版，右上角统一进入历史版本；审核锁定后显示“审核中”并禁止撤回。
- 审核通过后进入发布池，不再进行第二轮系统审核。
- 发布列表将平台灯放在内容名称之后，优先于商品和类型版本；平台灯图案及显示顺序由“平台与店铺”统一维护。
- 发布管理支持“未发布”快捷筛选；列表和详情切换平台灯均需二次确认，关联商品、目标平台及各平台发布文案只在详情中编辑。
- 发布详情勾选平台后展开该平台的账号列表，同一内容在同一平台选择一个账号；多平台账号在“所属账号”字段中联动汇总，未选择时显示“未分配”。
- 发布详情按平台分别选择该平台下的商品，商品、账号、标题、文案和话题作为同一份平台发布资料保存；发布灯每次开关都保留事件记录。
- 商品管理列表字段可以作为钻取入口：“已挂账号”先选择具体账号，再进入带商品与账号条件的内容列表；短视频账号使用两列大卡片，“绑定商品”下拉展示各商品内容数量，“发布内容”直接进入账号内容列表。
- 平台与店铺支持新增、编辑、排序和启停；停用不删除历史关系，平台排序同步决定发布管理的平台灯顺序。
- 组织与权限采用配置化角色：员工只引用一个角色，角色分别配置操作权限和数据范围；账号、部门停用后保留全部历史记录，首次登录必须修改初始密码。
- 数据统计支持日期、平台、账号、商品和员工等维度，平台表现手工录入按次保留；操作日志记录成功与失败操作，普通用户不能修改或删除。
- 未配置外部 AI 服务时，发布详情使用结构化手工填写或 TXT 导入；AI 接入后再基于平台、商品和账号风格案例生成。
- 待审核列表按刷新生成快照；进入审核工作台后队列固定并占用内容，审核结果批量确认后才正式提交。
- “推荐案例”与通过、驳回一起暂存并提交，正面或反面含义由审核评语说明；推荐绑定当前审核版本，并自动设置为公司内部公开。
- 同一来源内容在同一平台只能分配一次，删除记录不释放该唯一标记。
- 跨平台版本是不同内容条目，通过关联组比较；同一内容的修改文件使用 V1、V2、V3 版本链。
- 只有审核驳回且当前账号是原上传人时，内容池才显示“上传新版本”；公开范围和管理员身份都不能替代原上传人。提交新版本需二次确认，并重新进入审核中心。
- 每条业务内容只有一条线性版本链；只有当前已驳回版本可由原上传人生成一次下一版本，旧版本自动转为历史，不再污染日常列表。
- 版本管理按“一条内容一行”展示最新版本；历史源文件只允许超级管理员清理，版本元数据、审核意见和操作日志始终保留，推荐或发布中的版本不可清理。
- 版本管理总页按“一条内容一行”展示，可勾选内容批量删除其全部历史版本；点击详情可预览、下载或精确删除单个历史版本，所有删除均需二次确认。
- 图文的新版本必须一次上传完整图片集合；所有长列表使用固定窗口滚动和吸顶表头。
- 所有业务列表统一使用一套直观的“筛选条件栏”：直接显示当前页面最常用的关键词、状态、人员和时间范围，低频字段收进同一栏的“更多条件”；不再要求员工理解 AND、OR、NOT。二级页面返回时保留筛选状态，重新从左侧导航进入时刷新。
- 推荐案例与审核通过或驳回同时提交，自动公开并绑定被审核的具体版本；工作台可直接预览该版本，退出预览仍回到原工作台位置。
- 超级管理员可修改所有员工账号的姓名并重置密码；其他账号管理角色只维护部门、角色和启停状态。
